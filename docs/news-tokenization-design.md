## 現行實作與驗證界線

- **版本與詞典**：`requirements-news.txt` 固定 jieba 0.42.1 與套件 hash；繁體基底詞典隨庫保存、依 manifest 驗證 checksum，領域詞以來源可追溯的 JSON 維護。`dictionaryHash` 識別基底與領域檔的原始 bytes，修改領域詞或來源會改變 hash。完整來源與契約見 [詞典說明](../scripts/lexicon/README.md)。
- **HMM**：實作固定 `cut_all=False, HMM=False`。這是目前技術設定，不是把早期詢問語料來源追溯當成已選擇關閉 HMM；也未據此宣稱完成 HMM 開關的語意效果比較。
- **呼叫與位置**：Node 的 `tokenizeArticle` 啟動 Python 子程序，`understandArticle` 及上層入口使用 `await`。title／body 分別保留完整字串，Python 碼位轉成 JS UTF-16 `start/end`，end 不含結尾；Node 以原文 `slice` 核對，連空白、換行及非 BMP 字元也保留。來源 adapter 擷取後的文字是此介面的原文，不是網頁 HTML 的 offset。
- **環境與故障**：本機與 Actions 使用同一份固定依賴與詞典；Actions 設定 Python 3.12。斷詞不下載字典，必要依賴、checksum 或輸出驗證失敗即停止更新，不能退回舊規則繼續發布。
- **事件與發布**：酒精／毒品主張、人物及事件規則由理解模組處理，records 再分別核對新聞、事件、定位與傷亡欄位；已串接每日快照、重播與 GitHub publisher，正式部署及線上讀回仍未完成。政策／統計只進新聞，疑似候選不自動納統計。
- **可選 Gemini**：接點已實作，只保存引句與位置核對後的 suggestions，人物關係仍未驗證，不改變 eligibility。`NEWS_API_MAX_REQUESTS` 是每次執行上限，state 的日期／累計 requests 不是每日硬額度。目前沒有金鑰、API 實測或效果量測。

安裝、可執行 CLI、發布與恢復步驟以 [README](../README.md#安裝本機新聞環境) 為唯一操作來源，本頁不維護另一套命令。原文回看由 [回看報告](news-understanding-backtest-2026-11-03.md) 維護；固定 hash、位置核對與程式實作不代表精確率或全自動語意理解完成。

## 前幾輪已確認的需求（歷史紀錄，以上方最新變更為準）

- 本次一併重整人物與事件關聯，範圍不限於詞彙辨識（Q1 已答）。

- 斷詞程式或詞典無法使用時，停止當次更新、保留既有資料並記錄失敗，不退回舊規則繼續產生候選（Q3 已答）。
- 執行與排程可在 GitHub Actions 進行，不依賴 Codex 自動更新。
- 本機能執行相同工作，README 提供對應指令。
- 自動建立待複核資料 PR，合併後更新網站。
- 收錄具體毒駕上路事件，區分造成事故、危險駕駛及毒駕上路，包含零死傷。
- 每個判斷保留原文依據；人物、物品、施用、檢測、拒測與待驗分開。
- 先完成方法與腳本，再用舊聞及近期文章回看；不能以測試通過數代替文本判讀完成度。

## 歷史第一輪：回答與當時待決事項

### Q1：這次要改到哪一層？

第一種是讓 jieba 改善毒品、檢測與行為詞彙的辨識，保留原文位置，沿用既有人物、事件及傷亡規則。第二種是本次同時重整人物與事件關聯，這需要額外的關係解析設計。

使用者選擇第二種：**本次也重整人物與事件關聯**。原本僅做詞彙接入的建議未被採納，不得以附加斷詞結果卻不改關係判讀來交付。

### Q2：遇到詞典沒有的新詞，允許推測切詞嗎？

例如新的毒品俗稱。jieba 的 HMM 在本機執行，不需要模型 API；無論是否開啟，推測出的新詞都不能單憑斷詞結果認定為毒品。

使用者當時沒有選擇 HMM 開關，改問是否有線上文本資源，或能否以過去新聞作為斷詞語料來源。當時先查證來源及區分詞典、未標註新聞、斷詞標註與人物／事件標註；不能把這個追問解讀成當時已同意關閉 HMM。後續實作設定另見上方現行狀態。

### Q3：斷詞程式或詞典無法使用時，當次更新怎麼處理？

使用者已選擇：**停止更新並記錄失敗**。這裡指環境故障或詞典讀取失敗，不是一般陌生字詞；停止時保留既有資料，不靜默降級。

## 歷史第二輪：Q4 跨篇關聯

情境：同一事故初報三人受傷，隔日其中一人不治。使用者要求重整人物與事件關聯後，需要確認是否同時處理這種跨篇狀態變化。

使用者當時回覆「減少人為介入的時間」，未逐一選擇原有選項。當輪提案為：具明確同案依據且無身份矛盾者，自動整理配對與事件更新，PR 呈現變更；只有身份歧義、來源衝突與重要數值變更集中列出依據。當時不把這句回覆解讀為取消資料 PR、允許自動發布或無條件覆寫已複核資料。後續已由 Q6／Q7 與 ADR-0002 明確改採直接發布及欄位分別核對。

## 語料來源調查結論

有現成繁體詞典、已斷詞語料及官方毒品用語，歷史新聞也能作為領域語料；用途與使用條件見 [來源盤點](news-corpus-sources.md)。建議以「現成繁體詞典＋官方領域用語＋歷史原文」建立可追溯的詞彙與句型材料；已用於修正的 23 篇是開發材料，另保留按事件分組的新文章作後續回看。

語料取得不等於自動學到人物與事件關係。以減少人工時間為目標，由程式先產生詞彙及事件標註候選，確認過的少量標註另存；不能把舊程式輸出的錯誤自動重新當成真實答案。

## 接入前提案（歷史，已由現行流程取代）

1. 使用現成繁體詞典及有來源的毒品名稱／別稱，歷史新聞自動整理候選詞與上下文，不從零訓練斷詞模型。
2. 重整人物與事件規則，將人物提及、別稱、角色、車輛、行為、檢測對象及傷亡狀態連到同一事件及原文位置；人物關係不僅由最近出現的姓名決定。
3. 跨篇配對需明確同案引用，或事發日期、具體地點與當事人資訊一致且無矛盾。相同縣市與傷亡數不能單獨觸發合併。
4. 同案後續資訊按時間整理成更新，保留原始來源與更正紀錄；不把初報、後續報導的死傷直接相加。歧義與衝突集中列於 PR。
5. 本機與 Actions 使用固定版本的程式、字典及依賴；執行失敗停止更新。資料 PR 保留整批確認，網站只在合併後更新。

當時具體提案：**現成詞典與官方用語打底，歷史新聞自動整理詞彙及事件候選，有明確同案依據者先整理成合併更新結果，歧義及衝突集中複核，最後保留一個資料 PR 的整批確認。** 其中資料 PR 已被後續決策取代；歷史新聞自動整理詞彙的提案也不表示目前已有自動學習流程，現行領域詞典仍需維護來源。

當時把 HMM 開關列為實作比較項：使用固定版本與同批原文比較詞界後再決定設定。後續程式已固定 false，但這份紀錄沒有 HMM 語意效果比較結論；不論開關，都不能把切出的新詞直接當作毒品、人物身分或傷亡證據。

這一階段當時只更新設計文件、尚未接入程式；此階段已結束。自動化界線與目前已接入的程式以頁首狀態及 ADR-0002 為準。

## Q5 數值衝突：歷史提問與現行結論

情境：既有已複核事件為兩人受傷，新報導說三人受傷，但無法確定是傷勢更新、更正或新聞誤植。自動化無法只靠「較新文章」或「取較大值」裁決。

當時提出保留已複核值並列出衝突，或暫時移出統計兩種方案，沒有從「減少人工」推定答案。後續 Q7 已選定保留既有已核對值及新來源，集中處理例外。此保留規則不適用未核對 legacy 值；強證據可重新核對並留下變更紀錄，仍未明的欄位不參與數值統計。

## 接入前的技術盤點（歷史）

- 當時 `scrape_news.mjs` 與 `analyze_news.mjs` 共同呼叫 `understandArticle(article)`，前者同步、後者已用 `await`；接入後已統一 async 呼叫，更新入口現為 `update_news.mjs`。
- 當時新聞 workflow 只有 Node，尚無 Python／jieba 安裝或版本鎖定；現已加入固定環境。暫存環境的示例執行仍不能代替正式部署驗收。
- 當時 `evidence` 只有語句編號與引文；現已保留 `field/start/end`。正文清理與子句串接可能改變位置，後續修改仍不能把 jieba offset 直接套入另一版文字。
- Python 字串索引與 JavaScript `slice` 的單位不同，非 BMP 字元需轉換；原文位置對齊屬於實作責任，不要求使用者選擇編碼細節。
