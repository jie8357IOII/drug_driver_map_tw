# 酒駕／毒駕每日更新：實作與原文回看

日期：2026-11-03，Asia/Taipei。程式與本機驗證已完成，尚未 push、合併或部署。本文記錄實際執行結果；排程檔存在不代表 GitHub 排程已啟用。操作指令見 [README](../README.md#每日酒駕與毒駕新聞)。

## 已接通的流程

`LTN 搜尋與全文 → jieba／專用詞典 → 人物、事件與證據規則 → 同案整合與欄位核對 → 快照 → GitHub Actions 建置與發布`。

來源、理解、資料一致性及發布分別由 `ltn_article.mjs`、`news_understanding.mjs`、`news_records.mjs`、`publish_news.mjs` 負責，`update_news.mjs` 串接同一本機／Actions 入口。Python 只負責固定版本的 jieba；HMM 關閉，詞典雜湊及 UTF-16 原文位置均會核對。

新聞與事件分開。政策／判決／統計可進新聞區，未知傷亡保持未明；只有通過駕駛、事件時間與原文核對的事件計件，傷亡另按欄位資格加總。已核對值遇到無法說明的不同數值時保留原值，明確更正才可更新。

排程設定台北時間 00:17 與 08:17，與程式部署共用 Pages 鎖。快照先保存於 `news-data` 再部署，未完成的版本先重試；線上三份 JSON、code SHA 與 snapshot ID 讀回通過才記錄發布成功。生成時實際讀入的 base/state 原始 bytes 雜湊寫入 manifest，防止舊快照覆蓋新基準。首次從已合併歷史匯入拒收清單，不讀取未合併資料 PR。

## 回看材料與結果

先使用原先 23 篇毒駕材料與新增 10 篇文章，共 33 篇進行方法修正。之後實際執行 `news:update --from 2026-11-02 --to 2026-11-02`，搜尋五組詞並取得 15 篇全文，其中 6 篇不在前一批；去重後共 **39 篇**。發現日期／角色問題後，使用保存原文再重播。

## 已執行驗證

- 真實來源搜尋、全文擷取及本機快照生成成功；重播使用固定全文，不重新下載新聞。
- 相同 base/state 與文章接續重跑，事件及新聞 JSON 不重複、資料變更時間不漂移；離線重播水位保持 null。
- 回歸檢查包含原文 offset、角色／檢測分離、否定、政策／頁尾、未知值、同案衝突、明確更正、快照雜湊、故障停止及拒收歷史；測試中的人物範例是人工編寫情境，並非真實案件。
- `npm test` **15/15 通過**；`npm run data:validate`、Pages 模式 build，以及 JS／Shell／三份 YAML 的內嵌 Bash／差異檢查通過。測試通過數不替代原文理解驗收。
- 桌面與 390px 手機瀏覽器檢查酒／毒篩選、政策新聞、未知傷亡與縣市彙總；台北時間顯示正常。公開網站版本由部署時的 `news-build.json` 提供，本機單純複製資料預覽不偽造發布時間。
- 本機執行環境為 Node 22.23.2、Python 3.14.7／jieba 0.42.1。Actions 已設定 Python 3.12，但尚未在 GitHub runner 實跑。

## 尚存限制

來源目前只有 LTN。複雜親屬、沒有切換線索的多案、跨段日期、同案身分與傷亡更正仍可能不能判定；這些留在待釐清資訊，不以詞典命中代替語意證明。只有明確條件支援的跨篇合併與狀態更新會自動採用，不能宣稱所有後續報導都能自動整理。

例如 5450382 同時出現事發與追捕城市，目前公開層保守暫緩定位；5451180 的部分傷亡未通過原文／人物核對，欄位維持未知。歷史多案混成一筆的資料不強行配成單一新事件。仍有 68 筆歷史資料需要逐步回看，不能靠本批測試自動升格。

Gemini 接口只提供原文引句核對過的關係建議，未取得 API 金鑰、未呼叫雲端模型；建議不提高發布資格。正式 GitHub 運行、Pages 部署與線上 hash 讀回尚未執行，需程式合併至 main 後首次初始化。

逐篇判讀結果與正文 SHA-256 見 [結果 JSON](news-backtest-results-2026-11-03.json)，不包含全文；重抓清單見 [news-backtest-urls.txt](news-backtest-urls.txt)。重抓會取得網站當時版本；精確重現需保存當次 `sources.json`，以 README 的 `news:replay --input` 操作。全文與分析產物不提交或部署到網站。
