# 新聞理解方法：jieba、事件規則與發布核對

此方法先整理事件與人物，再形成網站資料。主流程使用 Node.js 事件規則與 Python jieba 斷詞；每日抓取和歷史回看使用同一套理解及快照核對流程，不依賴 Codex 排程。可選 Gemini 只產生經原文引句核對的 suggestions，不參與發布資格判定。

截至 2026-11-03，jieba、酒精／毒品解析、`news_records.mjs` 及 GitHub publisher 已實作，尚未部署。原文回看持續進行，未宣稱精確率或全自動語意理解完成。舊版純 JavaScript、禁止 API 及逐批資料 PR 的流程已由 [ADR-0002](adr/0002-automatic-news-publication.md) 取代；歷史訪談見 [接入設計紀錄](news-tokenization-design.md)，目前操作以 [README](../README.md#每日酒駕與毒駕新聞) 為準。

## 處理順序

1. **保留原文**：保存標題、發布時間、正文及來源網址。去除圖片說明、廣告與導覽，但不因標題提到法院或政策就先丟棄正文。
2. **斷詞與標記語句**：固定 jieba 0.42.1、隨庫繁體與領域詞典、`HMM=false`；驗證基底 checksum，記錄複合 `dictionaryHash`。保留段落、語句編號及 `field/start/end`；位置是來源 adapter 輸出的 title／body 各自的 JS UTF-16 區間，end 不含結尾，不是 HTML 位元組位置。Node 核對原文切片；切詞不改寫空白、換行與字元。宣導、回顧、否定及不確定描述不刪字後當作肯定句。
3. **分辨事件**：依明確的另案、第一／第二案、不同當事人與事件段落分案。共同導言的全篇統計不直接分配給任一事件；不能可靠分案時提出待複核原因。
4. **建立當事人**：把姓名、姓氏稱謂、年齡及親屬稱謂連結起來。區分肇事駕駛、受害者、乘客與處理事故的員警。遇到同姓且無法辨識、代稱無法回指時，不任意指派。
5. **連結車輛、時間與地點**：車輛必須綁定使用它的當事人；區分肇事車與被撞車。辨識事發地、居住地、逮捕地。以發布日解讀明確的昨日、前日等相對日期，保留解析依據與精度。
6. **分開整理酒精與毒品主張**：每個查獲、施用或檢測敘述都要辨識對象。酒精數值保留單位、檢體與駕駛關聯，不把呼氣與血液結果互換。毒品區分人體與物品檢測；兩者都分開記錄陽性、陰性、待驗、拒測、疑似、自述與已排除，乘客結果不能移給駕駛。
7. **整理傷亡**：先取有範圍的明示總數，再整理可辨識當事人的最終狀態。重複提到同一人不重複加總；同一人後來死亡不再同時計為存活傷者。子集合、送醫總數、車輛數、年齡、罰款及歷年統計分開辨識。
8. **形成候選並分類新聞**：具體上路行為與酒／毒駕主張相關時可形成候選，包含疑似及零死傷、未碰撞事件；候選還須經發布核對。`eventType` 記錄交通經過，`impairmentTypes` 分別記錄 alcohol／drug。新聞分為 incident、policy、judicial、statistics、other；司法後續即使沒有 candidate，也可嘗試連到既有事件。
9. **核對發布與欄位資格**：`news_records.mjs` 依原文位置、人物角色、強主張、事發日與同案一致性決定事件資格，不採用模型 confidence 作為通行條件。新聞卡、事件數、定位與各傷亡欄位分別核對；未知、衝突及待確認不填成零或否定。policy／statistics 固定只發布新聞卡，不由其中的假設人物或法律數字新增／更新事件。

## 判斷約定

### 一篇文章與一次事故分開

明確有兩起案件的報導，應分別整理兩組人物、證據與傷亡。同一事件的多篇文章仍需事件關聯；URL 去重只能避免同一篇重複處理，不能證明兩篇是不同事故。

共同導言可以補充已辨識人物的年齡、性別及唯一縣市，不把全篇傷亡總數套入每起案件。原文明示案件數與分案結果不一致時，不輸出混合人物的候選，保留 `multiple_events_unresolved`。

跨篇自動合併需明確同案來源引用，或事發日期、具體路段、駕駛姓氏與年齡、相容車型一致且沒有身分矛盾。「同縣市＋相同傷亡」不構成充分條件。既有來源與 relatedReports 先建立來源索引；已知 URL 先核對，讓新文章沿用舊 ID。模糊配對保留在 state／report，不另外建立可能重複的統計事件；多案文章各有事件 ID，不能把一筆未拆分 legacy 硬套給多案。

同案後續可以更新已存在的事件與傷亡，無須一定有新 candidate。不同數值不相加、不按發布日期或最大值覆寫；可採用的更正或同一人狀態轉變需有 `updateKind`／`currentFacts` 與原文依據。state 保存最小 match keys、來源、history、issues 與有長度限制的引句，不保存全文。相同正文 hash／理解版本重跑保留事件 ID 與既有資料，持久公開資料中的人工修改仍由 baseIncidents 延續。

### 人物與指代

人物身分至少需要明確稱謂或可回指的代稱。「林姓男子」「林男」在沒有同名競爭時可以合併；同姓但年齡不同的人不能合併。「姊姊」「妹妹」是兩個人物，「妹妹送醫後不治」仍是同一個妹妹。

年齡、性別、車輛、毒品與傷亡只能放到被原文支持的當事人身上。人物仍不明時，可保留事件層級資訊，但不把第一個出現的年齡或車輛直接套給駕駛。

### 證據狀態

- **已報導陽性／施用或明示酒駕**：強主張必須連到駕駛本人；不推論司法上的最終責任。`reported_positive_or_use`／`reported` 只是狀態條件，仍須核對原文及人物關係。
- **疑似或待確認**：疑似酒／毒駕、不排除、送驗待查、拒測等可留在相關新聞，不能單獨產生統計事件；`suspected` 不因有 candidate 就升格。
- **已排除／衝突**：酒精與毒品各自判讀，不能把「不排除」當作排除。`ruled_out`、`conflicting`、`not_supported` 本身不足以通過該類型的事件資格。
- **僅持有或物品含毒**：不能單獨認定本人施用或受影響。
- **其他人證據**：乘客、另一案件駕駛或過往事件的結果不能移用。

毒品名稱保留原文及可確定的別稱。法定級別不依關鍵字自行套用現行法；原文有記載時才作為報導資訊保留，無法判斷則未知。

毒品主張記錄 `kind`、`actorIds`、`status`、`timeScope`、`methods`、`substances` 與原文子句。檢測的要求、拒測、待驗、陽性、陰性分開；只有相同對象、時間與方法的後續結果，才能補回同次檢測。不確定是人體還是物品時保留 `unknown_test`。關鍵字是證據索引，不等於人體陽性清單。

酒精主張另外保存 `value`、`unit`、`specimen` 等資訊；未知單位或檢體不能自行補齊。本人否認吸毒不是陰性檢驗，不能遮掉已連到同一駕駛的客觀陽性；否認仍留為 issue。來源中的否定或不確定語句與結構狀態不一致時，發布器保留疑義。

### 數量與狀態變化

- 明示全案總數有自己的範圍；「其中一人重傷」是既有傷者的子集合。
- 人物計數按身分去重；依人物敘述整理的數量標示推導方式，不宣稱是官方完整統計。
- 死亡優先於同一人的先前受傷，保留兩段依據以說明更新。
- 「送醫四人、其中一人不治」只有在同一集合與先後關係明確時才能推導存活傷者；否則保留矛盾／不完整原因。
- 人數衝突不能靠取最大、取最後出現或相加解決。
- 只有先前已核對的舊值才能作為衝突時保留的統計值，並留下 conflicts／history。未核對 legacy 舊值遇到已核對新值可重新核對，記錄 `rechecked_legacy_value`；新值仍未知時，舊數字只供查閱，`fieldStatus: unknown` 不參與加總。
- 完全未提到某種傷亡時保留未知；明示全案無死傷才是零。僅駕駛未受傷不能推成整案零傷亡。
- 只能確認下限時，同時呈現「至少幾人」與「總數未知」，不把下限當成精確總數。

## 快照、可選 API 與驗證範圍

實作已包含來源 adapter、async `understandArticle`、單篇／批次分析、每日更新／離線重播、`buildNewsSnapshot`／`validateNewsSnapshot` 及 GitHub publisher。新聞卡與事件分開，資料品質使用 `machine_checked`、`manual_checked`、`legacy`，各傷亡欄位另有 checked／unknown／conflict。已核對事件可在傷亡未知時計入事件數；城市已知才有地圖資格，不捏造精確座標。

Gemini 接點只有在設定金鑰與模型時啟用，對 suggestions 核對連續原文引句與字串位置，標記 `quote_checked_relation_unverified`。不驗證建議的語意正確性，不將建議寫入已核對事實、改變 eligibility 或覆寫傷亡。`NEWS_API_MAX_REQUESTS` 限制每次執行的請求數，不是每日硬額度；date／requests 是使用記錄。快取與設定方式見 [README：可選 Gemini 擷取建議](../README.md#可選-gemini-擷取建議)。目前沒有金鑰、API 實測或效果量測。

`news:update`／`news:replay` 預設只產生核對後的快照；`news:publish` 與 Actions 串接保存、部署及線上 hash 核對，日常資料不再逐批人工合併 PR。這些流程已實作但尚未部署，機器核對也不冒充人工複核。實際安裝、CLI、發布前提與恢復步驟統一見 [README](../README.md#安裝本機新聞環境)。

回看以原文證據、事件分案、人物歸屬、事發時間、酒／毒駕狀態、傷亡推導與缺漏原因逐項比對，結果另由 [回看報告](news-understanding-backtest-2026-11-03.md) 維護。無明確切換詞的多案、複雜親屬代稱、未具名傷者、隱含車種、跨段時間及缺少明示轉變訊號的後續報導仍有涵蓋限制。候選數、語法檢查或已用於修規則的回看材料，都不能代替獨立的精確率／漏收率評估。
